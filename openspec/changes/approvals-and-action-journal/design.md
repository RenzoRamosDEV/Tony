# Design

## Context

Observed code:
- `EdithGuard.decide` (`guard/edith.py`): `evaluate` -> for `confirm`, `_ask_user` builds a `ConfirmationRequest` (`task_id`, `tool`, `args_preview`, `question`, `allow_always`) and waits `confirm_timeout_s` on the `Confirmer`; result `allow`/`deny`/`timeout`; then one audit line.
- Two `Confirmer`s: `CliConfirmer` (in-process `ask`, reads a stdin line, used by `tony run` and `tony chat`) and `ConfirmationBroker` (desktop/voice: `ask` publishes `needs_confirmation` and awaits a future; `Runtime._dispatch` calls `broker.answer(task_id, decision)` for the `Confirm` command). Broker serializes asks with a lock, so at most one approval is pending.
- `PolicySource.current()` returns a parsed `Policy`; `LivePolicy.reload()` swaps it on file change; `load_policy` reads `agents/<guard>/policy.yaml`.
- `ToolProxy._judge_and_execute` calls `guard.decide`, then `_execute` (timeout via `wait_for`, errors turned into `ToolReply`). `audit.args_hash` is already sha256 of the canonical JSON of the unmasked args.
- `HistoryStore` pattern: one sqlite connection per store, schema via `executescript`, masker applied on write, injected clock.
- Previous change `phase1-conversations-doctor-policy` is present uncommitted (`inspector.py`, `policy` CLI group, `open_history`). This change touches none of its specs (`conversation-memory`, `chat-cli`, `diagnostics`, `policy-management`, its `core-events` additions are different requirement names) and only adds a new `actions` Typer group beside `policy`/`conversations` in `main.py`.

## Goals / Non-Goals

**Goals:** approvals bound to exact arguments, policy version and a deadline; authoritative masked previews; durable per-call journal with crash recovery; `tony actions` inspection.

**Non-Goals:** desktop UI changes (only the optional TS field types), reconciliation of `outcome_unknown`, replay/retry, changing `evaluate`, the shipped `policy.yaml` or PIN logic, journaling of calls that never run.

## Decisions

1. **Digest = existing `args_hash`.** `args_digest` reuses `audit.args_hash` (sha256 of canonical JSON of unmasked args). One definition across audit, event and journal.
2. **Policy version = sha256 of the `policy.yaml` bytes.** Add `load_policy_with_version(root, guard) -> (Policy, version)` in `guard/policy.py` (reads bytes once, hashes, parses; `load_policy` delegates, so behavior is unchanged). `PolicySource` gains `version() -> str`; `StaticPolicy(policy, version)` takes it at construction (runner computes it when it loads the policy), `LivePolicy` updates policy and version together in `reload()`, so a failed reload keeps both. Alternative (hash of the parsed model) rejected: comment-only edits would not matter but the requirement is file content, and it is deterministic and cheap.
3. **Expiry = `clock() + confirm_timeout_s`.** `EdithGuard` gains an injected `clock` (default `utc_now`; runner passes `deps.clock`) and sets `expires_at` from `policy.limits.confirm_timeout_s` when it builds the request. The existing `asyncio.wait_for` stays the enforcement of the timeout (`timeout` ruling); the broker additionally refuses answers whose time is past `expires_at`, so a late answer cannot race the timeout.
4. **Approval data travels in `ConfirmationRequest`.** New optional fields `approval_id`, `args_digest`, `policy_version`, `expires_at: datetime | None`, `preview: dict[str, str | int]` (defaults `None`/`{}`) so existing constructions and fakes keep working. `core_events.needs_confirmation` accepts them as optional keyword arguments and adds them to the event only when set (event stays valid for old consumers).
5. **Where the answer carries `approval_id`.**
   - Desktop/voice bridge: `Confirm` command gets `approval_id: str | None = None` (still `extra="forbid"`); `Runtime._dispatch` passes it to `broker.answer(task_id, decision, approval_id)`. The page already stores the whole `needs_confirmation` event (`page_protocol.py`), so a UI can echo the id; TS types gain the optional field in `NeedsConfirmationEvent` and the `confirm` command shape, with no UI behavior change (the current UI keeps omitting it and is served by the legacy path).
   - CLI: `CliConfirmer.ask(request)` is called with the specific request, so the answer is bound by construction; it needs no id. It prints the preview fields to stderr before the question so the user sees the authoritative content. Expiry is the guard's `wait_for`.
6. **Broker answer rules.** `answer(task_id, decision, approval_id=None, now=None)`: ignore when nothing pending, task differs, future done, `approval_id` given and different, or `now >= expires_at` (broker takes an injected `clock`, default `utc_now`). Ignored answers leave the approval pending until timeout. No id plus exactly one pending approval (always the case given the lock) is accepted.
7. **Re-check order in the guard.** `decide` loops (max 2 re-evaluations): read `policy` and `version`, `evaluate`, if `confirm` build the approval and ask; after an affirmative answer compare `self._policy.version()` with the approval's; if different, repeat from the top with the new policy (a changed policy may now allow, deny or ask again with a new `approval_id`); after the limit return `confirm` with `user_decision="deny"`. Only the final ruling is audited, with `approval_id` of the last asked approval. "Always allow" writes `policy.yaml` itself; the reload that follows changes the version and re-evaluation then returns `allow` by the new `user-always/` rule, which is the intended result and needs no second question.
8. **Arguments-changed check lives in the proxy.** The guard receives the same `args` object the tool will get; the only window for mutation is between ruling and dispatch. `ToolProxy` computes `args_hash` before `guard.decide` and again before `_execute`; mismatch returns `tool <id> was not executed: not confirmed by the user (arguments changed)`, supervisor `unconfirmed(..., "deny")`, no journal row. Applies to every verdict (cheap), not only confirm. `UserDecision` values are unchanged, so audit and TS types need no new literal.
9. **Previews in `guard/previews.py`.** `build_preview(tool, args, masker) -> dict[str, str | int]` with a table `tool -> field names`; each value is masked (`masker.mask_json` over `_mask_secret_keys`, reusing audit's helper made public as `mask_args`) then stringified (strings as is, other values as canonical JSON) and capped at 2000 characters plus `…`. Absent fields are omitted. `filesystem.write_file` `bytes` is `len(content.encode())` taken before masking/capping, `content` capped at 2000. Unknown tools: `{"args": canonical JSON of masked args}` capped. The `args_preview` string (200 chars) stays for compatibility.
10. **Journal location: sibling file `memory/actions.sqlite`.** Separate from `conversations.sqlite` so deleting or resetting conversations can never touch an audit-like record, and the two stores keep independent lifecycles. Module `core/memory/actions.py`: `ActionJournal(root, masker, clock)` with `prepared(task_id, agent, tool, args_digest) -> call_id`, `transition(call_id, state, detail="")`, `recover_interrupted(before)`, `list(state, limit)`, `get(call_id)`, `close()`. `detail` masked then cut to 200. Only the digest is stored, never arguments. The proxy depends on a small `ActionRecorder` Protocol in `orchestrator/ports.py` (`prepared`, `transition`), so tests use a fake in memory.
11. **Wiring.** `RunDeps.journal: ActionRecorder | None = None`; `_proxied_tools` hands it to `ToolProxy`. `Runtime` (desktop), `run_chat` and the `run` command create an `ActionJournal`, call `recover_interrupted(process_start)` once, pass it through `RunDeps` and close it on exit. `tony actions list/show` open the file read-only in effect (no recovery) via an `open_journal(root)` helper like `open_history`; a missing file is treated as empty without creating it.
12. **Proxy sequence.** hash -> `step` -> `guard.decide` -> (deny/unconfirmed return) -> hash re-check -> `prepared` -> `dispatched` -> execute -> `succeeded` / `failed` (reply error or exception, detail = masked error text) / `outcome_unknown` (timeout, detail = "timed out after Ns"). Cancellation (`CancelledError`) while dispatched leaves the row `dispatched`; startup recovery or a later run reports it as `outcome_unknown`. Journal calls run through one `_record` wrapper that catches exceptions, publishes a single `error` event per proxy and continues: the journal is evidence, not a gate, so a disk problem must not disable Tony (alternative fail-closed rejected as it would turn a logging fault into denial of service; trade-off recorded below).
13. **CLI.** `actions` Typer sub-app: `list --state/--limit` (validated against the five states, limit >= 1, default 20, newest first by `created_at` then rowid, output via the shared `table()`), `show CALL_ID` prints `column: value` lines. Errors exit 2 like phase 1 commands.

## Risks / Trade-offs

- Fail-open journal: an unwritable disk loses records silently except one `error` event. Accepted; stated in spec.
- Recovery marks `dispatched` rows of any older process: a second Tony process (e.g. `tony run` while the desktop is mid-call) could mark the other's live call `outcome_unknown`. The live process later overwrites with the true final state (transitions are unconditional), so the error is transient; a pid column was left out to keep the contract's columns.
- Concurrent sqlite writers across processes: default journal mode with a short busy timeout; writes are single-row.
- `Confirm` without `approval_id` remains valid, so a stale UI is not protected by the id; protection there is the broker's single pending approval, task match and expiry.
- Policy-version re-evaluation could in theory ask the user repeatedly if the file keeps changing; bounded by two re-evaluations then deny.
- Preview field of 2000 characters inflates the event; one pending approval at a time keeps it small.

## Migration Plan

Additive: new optional event/command fields, new sqlite file created on first use, new CLI group. No existing file is rewritten. Rollback is reverting the code; `memory/actions.sqlite` can be left or deleted.

## Testing Strategy

Failing tests first, fakes before mocks: in-memory `ActionRecorder` fake, fake clock, fake `Confirmer`/`PolicySource`, `tmp_path` sqlite for the journal. Cover equivalence classes per spec scenario; boundaries: preview exactly 2000 vs 2001 characters, `expires_at` equal to now vs after, `detail` 200 vs 201, limit 0/1; error guessing: policy edited during wait, args mutated during wait, unknown tool, secret in content, missing journal file, cancelled call. Existing fakes implementing `PolicySource` get `version()`. Mutation testing on the diff only (target above 95%, 3-minute cap, justify survivors).
