# Design

## Context

- Action journal (`tony/core/memory/actions.py`, from `approvals-and-action-journal`, uncommitted): `memory/actions.sqlite`, states `prepared|dispatched|succeeded|failed|outcome_unknown`, only an args digest, `detail` capped at 200 chars.
- `ToolProxy._judge_and_execute` is the single execution path: guard ruling, `prepared`, `dispatched`, `_execute`, final transition. `args` are available there.
- Task logs: `logs/tasks/<task_id>.jsonl`; first event `task_started {agent, task{objetivo,contexto,restricciones}}`, last event `task_finished {outcome}` (`ok|error|timeout|cancelled`). Envelope has `ts`. Subagent events share the parent's file. `agent_tools` also creates a log id without `task_started`.
- `run_task` (runner.py) is the only worker entry; `_prepare_run`/`_proxied_tools` are private. `Origin = Literal["text","voice"]` is the turn origin: validated by `SendMessage`, used by `reply_plan`, `turn_started` and the TS bridge type. It is not a task attribute.
- `EdithSession.unlocked` is the lock state; `SessionGate` prompts for the PIN, which a scheduler must never do. Default limits: task 300 s, confirmation 60 s.
- Hosts: `run_chat` (chat.py) and `CoreRuntime._start/_shutdown` (runtime.py, `_background` task list). CLI groups are inline in `create_app` (main.py, already ~630 lines).

## Goals / Non-Goals

**Goals:**
- Recovery and undo built only on journal, task logs and a small undo store; nothing is ever re-executed automatically.
- Deterministic, clock-injected scheduler, testable without sleeping.
- Every routine action goes through the existing guard, limits, journal.

**Non-Goals:**
- Calendar compensation, undo of deletes/moves/shell, undo of non-UTF-8 or >1 MB files.
- Background daemon, OS cron/systemd integration, notifications, desktop inbox UI.
- Retention/pruning of `memory/undo/` (follow-up).
- Multiple concurrent routine runs, sub-minute schedules, intervals other than daily/weekday.

## Decisions

### D1. Undo store: `memory/undo/<call_id>` plus sidecar
- `tony/core/memory/undo.py` `UndoStore(root)`: `keep(call_id, tool_id, args)`, `written_digest(tool_id, args)`, `load(call_id)`, `is_undoable(call_id)`.
- Files: `memory/undo/<call_id>` (previous bytes) and `memory/undo/<call_id>.json` `{"path": <args.path as given>}`. The journal has no path, so the sidecar carries it.
- `keep` only acts for `filesystem.write_file`; reads `Path(args["path"]).expanduser()`; skips (no files) when missing, `> 1_048_576` bytes, or not UTF-8 decodable (the restore is a text write). Files created with mode 0600; `memory/undo` created 0700.
- sha256 of written content = `sha256(args["content"].encode("utf-8"))`; journal `detail = "sha256=<hex>"` on `succeeded`.
- Alternative: store pre-image inside sqlite. Rejected: blobs up to 1 MB per call bloat the journal; files are trivially prunable.
- call ids are uuid4 generated by the journal; `load` validates the id against a uuid pattern before building a path (no traversal).

### D2. Proxy integration (port, non-blocking)
- New port in `ports.py`: `ActionSnapshots` with `keep(call_id, tool_id, args)` and `written_digest(tool_id, args) -> str`. `ToolProxy(..., snapshots=None)`; `RunDeps.snapshots` defaults None (feature off in unit tests).
- Sequence: `prepared` -> `snapshots.keep` (via `_record`-style wrapper: failure reported once as `error` event, call proceeds) -> `dispatched` -> execute -> `succeeded` with `detail=written_digest`.
- The infra read happens in the adapter, not the proxy; the domain proxy stays free of file I/O.
- Hosts (`running_journal`, `run_chat`, runtime) build `UndoStore(root)` next to the journal.

### D3. Recovery reads logs and journal
- `tony/core/recovery/tasks.py`:
  - `scan_tasks(root, clock, limit_files=200)`: newest 200 `*.jsonl` by mtime; stream-parse lines, skip malformed; require a `task_started`; capture agent, request, `ts`, `resumed_from`, last `task_finished.outcome`.
  - Recoverable = outcome in `{cancelled, timeout}` or no `task_finished` and `mtime` older than `STALE_AFTER_S = 900` (3x task timeout; avoids listing a task another process is still running). Tasks that appear as `resumed_from` of any scanned task are hidden.
  - `resume_request(task, succeeded_actions) -> TaskRequest` with the note prefix (Spanish, like agent prompts): `Acciones ya completadas en un intento anterior (no las repitas):` then one line per action `- <tool> (<updated_at>, llamada <call_id>)`, capped at 20 lines; followed by a blank line and the original `contexto`. Arguments are unavailable (journal keeps digests only); stated in the note.
- `ActionJournal.for_task(task_id, state=None)` added (query by `task_id`, oldest first).
- Task ids from the CLI are validated `^[0-9a-f]{32}$` before touching the filesystem.
- Resume runs `run_task(agent, request, deps, resumed_from=task_id)` exactly as `tony run` builds `RunDeps` (CliConfirmer, journal, snapshots). Exit codes reuse `USAGE_ERROR`/`TASK_FAILED`.

### D4. Undo through the guard
- `runner.run_guarded_call(agent_name, tool_id, args, deps) -> ToolReply` (public): loads the worker, `_prepare_run`, writes `task_started` (`objetivo: "undo <call_id>"`) and `task_finished` to a fresh task log, opens `_proxied_tools`, finds the proxied tool by id and awaits its handler. Guard, confirmation, supervisor limits, masking and journaling are therefore identical to a model-issued call; the undo write gets its own pre-image so an undo can itself be undone.
- Agent = the journal row's `agent`. If that agent is no longer a worker or lacks `filesystem.write_file`, undo exits with a usage error (no fallback agent).
- Check order: call exists -> `succeeded` -> tool is `filesystem.write_file` -> pre-image present -> current file sha256 equals journal `detail` -> guarded write. A missing/unreadable current file counts as changed. TOCTOU between check and write is accepted (single-user local tool); the write is guarded and logged.
- Alternative: write the file directly from the CLI. Rejected: bypasses guard and audit, violating the spec.

### D5. `routine` origin without touching turn `Origin`
- Routines run worker tasks via `run_task`, not conversation turns, so `Origin` (`text|voice`) stays unchanged: `SendMessage` validation, `reply_plan` and `types.ts` `Origin` need no edit, and a UI command cannot claim `routine`.
- New `TaskOrigin = Literal["routine"]` in `core_events.py`; `run_task(..., origin: TaskOrigin | None = None, resumed_from: str | None = None)`.
- `log_events.task_started(agent, task, *, origin=None, resumed_from=None)` and `core_events.task_started(..., origin=None)` add the key only when not None, so every existing golden/log test is untouched. `types.ts` gets an optional `origin?: "routine"` on the task_started event type.

### D6. Routine storage
- `tony/core/automation/store.py` `RoutineStore(root, clock)` over `memory/routines.sqlite` (same open pattern as `ActionJournal`: busy timeout 2 s, `CREATE TABLE IF NOT EXISTS`).
- `routines(id INTEGER PK AUTOINCREMENT, name, prompt, time 'HH:MM', weekdays INTEGER, timezone, enabled INTEGER, last_occurrence TEXT NULL, active_since TEXT)`.
- `routine_runs(occurrence_id TEXT UNIQUE, routine_id INTEGER, scheduled_for TEXT, started_at TEXT NULL, status, result)`.
- Two columns beyond the plain list: `active_since` (UTC; set on add and on enable, prevents backfill) and `scheduled_for` (UTC instant, to re-check the 12 h limit after queueing). `routine_id` supports inbox joins; inbox uses LEFT JOIN so removed routines keep history.
- `weekdays` bitmask: Mon = bit 0 ... Sun = bit 6; default 127; CLI parses `mon,tue,...` case-insensitively.
- `time` stored `HH:MM`, validated by `datetime.strptime("%H:%M")`.
- `tz` validated with `ZoneInfo(name)`; default from `local_zone_name()` (env `TZ` if IANA-valid, else the `/etc/localtime` symlink target after `zoneinfo/`, else `UTC`), injectable for tests.

### D7. DST and occurrence ids
- `tony/core/automation/occurrences.py`, pure: `occurrences(routine, now) -> list[Occurrence(id, scheduled_for_utc)]`.
- `local_now = now.astimezone(ZoneInfo(tz))`; candidate local dates from `(local_now - 12h).date()` to `local_now.date()`; keep dates whose weekday bit is set.
- Instant = `datetime(y, m, d, H, M, tzinfo=zone, fold=0).astimezone(UTC)`. The id uses the configured `y-m-d` and `HH:MM`, never the converted time.
  - Ambiguous (fall back): `fold=0` picks the first instance; one id per date -> runs once.
  - Nonexistent (spring forward): `fold=0` uses the pre-change offset, so the instant is one hour of wall time later than configured; still one id -> runs once.
- Due = instant <= now and instant >= `active_since`. Late = now - instant; `> 12 h` -> `skipped`.
- Tests use `Europe/Madrid` 2026-03-29 (gap 02:30) and 2026-10-25 (repeat 02:30), plus a UTC-negative zone.

### D8. Scheduler with injected clock
- `tony/core/automation/scheduler.py` `RoutineScheduler(store, run, *, clock, unlocked, sleep=asyncio.sleep, interval_s=30, publish=no_op)`.
  - `run: Callable[[Routine], Awaitable[RunOutcome]]` is the task launcher; `unlocked: Callable[[], bool]` wraps `EdithSession.unlocked`.
  - `tick()` does the work once: (1) mark stale claims (`queued`, `started_at` older than 600 s) `error` "interrupted"; (2) for each enabled routine insert due occurrences with `INSERT OR IGNORE` (`skipped` if > 12 h late else `queued`) and set `last_occurrence`; (3) if `unlocked()`, take queued runs oldest first, re-check 12 h, claim with `UPDATE ... SET started_at=? WHERE occurrence_id=? AND started_at IS NULL` (rowcount 1 wins, so two live processes never double-run), await `run`, write `ok`/`error` + masked result capped at 2000 chars.
  - `run_forever()` = loop `await tick(); await sleep(interval_s)`; each tick wrapped in try/except publishing `error` (source `routines`) so a failure never ends the loop.
- Tests call `tick()` with a mutable fake clock and fake `run`/`unlocked`; no sleeping, no real time.
- Sequential execution: one routine task at a time inside a tick.

### D9. Task launcher and hosts
- `automation/launcher.py` `routine_runner(deps, worker_name, masker)` -> `run_task(worker, TaskRequest(objetivo=routine.prompt), deps, origin="routine")`; outcome `error` when `result.errores`. Worker = `slots.worker.name`. Cancelled/timeout surface as `errores` already.
- `run_chat`: after building the session, create store and scheduler (`unlocked=lambda: session.unlocked`), `asyncio.create_task(scheduler.run_forever())`, cancel and gather in `finally` before `journal.close()`. Routine tasks use the chat's `RunDeps` with `publish` replaced by a no-op (results reach the user only through the inbox, so `ChatPrinter` prints nothing for them) but the same confirmer: an unanswered confirmation is denied by the confirm timeout; a typed line during a routine confirmation can answer it (known sharing of the console).
- `CoreRuntime._start`: same, appended to `_background`; closed in `_shutdown`. Routine confirmations flow through `ConfirmationBroker` like any task.
- Locked sessions: no PIN prompt; `conversation_only` sessions stay locked, so routines stay `queued`.

### D10. CLI structure
- Two new modules `tony/apps/cli/recover_commands.py` and `routines_commands.py`, each exposing `add_*_app(app, ...)` called from `create_app` (injected `now`, engine/readline factories reused). main.py gains only registration lines.
- Output tables reuse the existing `table()` helper style of `actions_table`.

## Risks / Trade-offs

- [Interrupted detection by age (15 min) can hide a genuinely crashed recent task] -> acceptable delay; threshold is a named constant.
- [Resume note lacks arguments (journal stores digests)] -> note lists tool, time and call id; the agent is told not to repeat; accepted limitation.
- [Pre-image read races with the write] -> negligible locally; failure only loses undoability.
- [sha check is not atomic with restore] -> accepted; guard + audit still apply.
- [Undo store grows] -> bounded 1 MB per write; pruning is follow-up.
- [Missing system tzdata makes `ZoneInfo` fail] -> add/validate reports usage error; run-time failure of one routine is caught per tick and published.
- [Chat console shared by routine confirmations] -> documented; denied after confirm timeout when unanswered.
- [Two processes (chat + desktop) both schedule] -> unique occurrence id and claim UPDATE make runs once-only.
- [Routine prompt may contain secrets] -> stored as typed in the user's local DB; results are masked.
- Backward compatibility: all log/event additions are optional keys; new SQLite files are created lazily; no existing data migrated; rollback = ignore files.

## Migration Plan

1. Land prerequisites (the three uncommitted changes) first.
2. Ship additive code; new files `memory/undo/` and `memory/routines.sqlite` appear on first use.
3. Rollback: revert code; remove the two paths if wanted; nothing else reads them.

## Open Questions

- Retention policy for `memory/undo/` (age or count) can be decided later without changing specs.
